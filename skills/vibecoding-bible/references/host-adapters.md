# Host adapters: канон поверх разных агентных сред

Библия описывает роли, а не механизмы конкретного хоста. Этот файл сопоставляет роли с
примитивами сред, где skill фактически установлен. Правило одно: использовать
существующий примитив хоста, а не имитировать его перепиской в чате, и не выдавать
отсутствующий примитив за имеющийся.

## Соответствие ролей

| Роль канона | Codex | Claude Code | Общий случай |
|---|---|---|---|
| Вызов Библии | `$vibecoding-bible` | `/vibecoding-bible` либо автоматический выбор по description | Явный вызов skill средствами хоста |
| Делегирование bounded subtask (`DELEGATE`, `PARALLELIZE`) | Субагент/задача хоста | Субагент с собственным контекстом и ограниченным инструментарием | Отдельный исполнитель с exact objective, scope, invariants и required evidence |
| Планирование до изменений | Явный план в ответе | Plan mode — план утверждается до правок | Отдельный шаг «план → подтверждение → изменение» |
| Автоматическая проверка на событие | Внешний CI/скрипт | Hooks на события инструментов | Детерминированный скрипт в CI |
| Независимая проверка изменений | Отдельная сессия-ревьюер | Команда code review хоста либо отдельная сессия | Ревьюер, не являющийся автором изменения |
| Ограничение прав | Sandbox/permissions хоста | Permission mode и списки разрешённых инструментов | Least privilege средствами среды |
| Долгая возобновляемая работа | Внешний harness | Внешний harness | [`agent-harness.md`](agent-harness.md) |
| Специализированные skills | Установленные skills среды | Установленные skills среды | Проверить фактическую доступность до ссылки на них |

## Правила

Проверять фактическую доступность примитива, а не предполагать её по названию среды.
Если примитива нет, назвать это прямо и предложить честный manual fallback с теми же
границами: exact scope, evidence и человеческое подтверждение.

Не дублировать примитив хоста в чате. Если хост уже утверждает план, ведёт состояние
или запускает проверки, Библия остаётся policy layer и не строит вторую машину состояний.

Делегирование не меняет ответственность: оркестратор проверяет artifacts и tests, а не
summary исполнителя. Субагент, исправивший дефект, не подтверждает собственное
исправление.

## Условные зависимости

`shadcn` и `mastra` — conditional defaults, а не требования канона. Перед ссылкой на них
проверить, что соответствующий skill действительно установлен в текущей среде, и что
проект действительно на них построен: `components.json` для shadcn, установленные пакеты
`@mastra/*` для Mastra. Если skill отсутствует, работать по официальной документации
exact version и сказать пользователю, чего не хватает.

## Идентичность skill

`agents/openai.yaml` описывает интерфейс для Codex и другими хостами не читается.
Синтаксис вызова различается по хостам; версия skill одна и берётся из `VERSION`.
Не выводить версию из host-specific файлов.
